# TodoList 도메인 정의서

버전: 1.2 / 수정일: 2026-07-29 / 이전 버전 대비 변경: 필터링 기준 정의(7장), 범위 외 사항(8장) 추가

## 1. 개요 및 목적

TodoList는 인증된 사용자가 개인별로 할일(Todo)을 등록·관리할 수 있는 애플리케이션이다.
기존에는 사용자별로 할일을 독립적으로 관리할 수 있는 서비스가 부재했고, 특히 할일에
시작일과 종료일(기간)을 부여하여 일정 기반으로 진행 상태를 추적할 수 있는 기능이
필요했다. 본 문서는 시스템 설계에 앞서 TodoList가 다루는 핵심 개념, 용어, 엔티티,
상태, 비즈니스 규칙을 정의한다.

## 2. 핵심 용어 정의 (Ubiquitous Language)

| 용어 | 정의 |
|---|---|
| 사용자 (User) | 회원가입 후 인증(로그인)을 거쳐 시스템을 이용하는 주체. 자신이 등록한 할일과 카테고리만 관리할 수 있다 |
| 할일 (Todo) | 사용자가 수행해야 할 작업 단위. 제목, 카테고리, 시작일자, 종료일자, 완료 여부 등을 가진다 |
| 카테고리 (Category) | 할일을 분류하는 그룹. 사용자가 지정하지 않으면 '기본' 카테고리가 자동 적용된다 |
| 상태 (Status) | 할일의 진행 상황을 나타내는 값. 저장된 값이 아니라 매 조회 시점에 파생 계산된다. 상세 판단 기준은 4장 참조 |
| 소유자 (Owner) | 할일 또는 카테고리를 생성한 사용자. 해당 리소스에 대한 조회·수정·삭제 권한을 가진 유일한 주체 |
| 필터 (Filter) | 할일 목록 조회 시 카테고리 필터와 상태 필터를 함께(AND 조건) 적용해 결과를 좁히는 조건. 두 필터는 동시에 지정할 수 있다 |

## 3. 핵심 엔티티

### 3.1 사용자 (User)
- 속성: 사용자ID, 이메일(로그인 계정), 비밀번호, 닉네임, 가입일시
- 사용자는 자신의 계정 정보(닉네임, 비밀번호 등)를 수정할 수 있다

### 3.2 카테고리 (Category)
- 속성: 카테고리ID, 이름, 소유자(사용자ID)
- 사용자별로 여러 개의 카테고리를 가질 수 있다
- 모든 사용자는 별도 생성 없이도 '기본' 카테고리를 암묵적으로 보유한 것으로 간주한다

### 3.3 할일 (Todo)
- 속성: 할일ID, 제목, 설명(선택), 카테고리, 시작일자, 종료일자, 완료 여부, 완료일시(선택), 소유자(사용자ID), 생성일시, 수정일시
- 상태는 별도 저장 필드가 아니라 완료 여부와 시작일자·종료일자를 기준으로 파생된다. 판단 기준은 4장 참조

### 3.4 엔티티 관계
- 사용자 1 : N 카테고리 — 한 사용자는 여러 카테고리를 가질 수 있다
- 사용자 1 : N 할일 — 한 사용자는 여러 할일을 가질 수 있다
- 카테고리 1 : N 할일 — 하나의 할일은 정확히 하나의 카테고리에 속한다
- 모든 카테고리와 할일은 소유자인 사용자에게 종속되며, 사용자 간 데이터는 공유되지 않는다

## 4. 할일 상태(Status) 정의

할일의 상태는 DB에 별도 필드로 저장하지 않고, "완료 여부"와 "현재 날짜 대비 시작일자/종료일자"를
기준으로 조회 시점에 계산되는 파생 값이다. 판단 기준은 다음과 같다.

| 상태 | 판단 조건 |
|---|---|
| 시작 전 (Not Started) | 완료되지 않았고, 현재일자 < 시작일자 |
| 진행중 (In Progress) | 완료되지 않았고, 시작일자 ≤ 현재일자 ≤ 종료일자 |
| 완료 (Completed) | 완료 처리된 할일 (완료 시점의 일자와 무관) |
| 기한초과 (Overdue) | 완료되지 않았고, 현재일자 > 종료일자 |

완료 여부(완료/미완료)만 실제 저장 데이터이며, 나머지 세 상태(시작 전/진행중/기한초과)는
미완료 할일에 한해 날짜 비교로 구분된다.

## 5. 핵심 비즈니스 규칙

1. 회원가입 및 로그인(인증)을 완료한 사용자만 할일과 카테고리를 생성·조회·수정·삭제할 수 있다.
2. 할일 등록 시 카테고리를 지정하지 않으면 '기본' 카테고리가 자동 적용된다.
3. 할일의 종료일자는 시작일자보다 이전일 수 없다 (같은 날짜는 허용). 위반 시 저장 시점에
   유효성 오류로 거부하고 할일을 생성·수정하지 않는다.
4. 할일과 카테고리는 소유자 본인만 수정·삭제할 수 있다 (타 사용자의 데이터에 접근 불가).
   본인 소유가 아닌 리소스에 대한 조회·수정·삭제 시도는 해당 리소스가 존재하지 않는 것과
   동일하게(404 Not Found 수준) 처리하여 존재 여부 자체를 노출하지 않는다.
5. 사용자는 자신의 계정 정보를 스스로 수정할 수 있다.
6. 할일의 상태는 저장값이 아닌 파생값이며, 판단 기준과 우선순위(완료 처리된 할일은 종료일자
   경과 여부와 무관하게 '완료'로 간주)는 4장을 따른다.
7. 사용자가 소유한 카테고리를 삭제하면, 해당 카테고리에 속한 할일은 삭제되지 않고 모두
   '기본' 카테고리로 자동 이관된다.

## 6. 주요 유스케이스

| # | 유스케이스 | 액터 | 설명 |
|---|---|---|---|
| UC-1 | 회원가입 | 비회원 | 이메일 등 정보를 입력해 계정을 생성한다 |
| UC-2 | 로그인 | 사용자 | 인증 후 자신의 할일 데이터에 접근한다 |
| UC-3 | 계정 정보 수정 | 사용자 | 자신의 계정 정보를 수정한다 |
| UC-4 | 할일 등록 | 사용자 | 제목, 카테고리(선택), 시작일자, 종료일자를 캘린더로 지정하여 할일을 생성한다. 카테고리 미지정 시 '기본' 카테고리 적용 |
| UC-5 | 할일 목록 조회 | 사용자 | 자신의 할일 목록을 조회하며, 카테고리 필터와 상태 필터(4장 기준)를 동시에(AND 조건) 적용하여 필터링한다 |
| UC-6 | 할일 수정 | 사용자(소유자) | 편집 화면에서 제목, 카테고리, 시작일자, 종료일자, 완료 여부(완료 처리/취소 포함) 등을 수정한다 |
| UC-7 | 할일 삭제 | 사용자(소유자) | 자신의 할일을 삭제한다 |
| UC-8 | 카테고리 생성 | 사용자 | 이름을 지정해 새 카테고리를 생성한다 |
| UC-9 | 카테고리 수정/삭제 | 사용자(소유자) | 카테고리 이름을 수정하거나 카테고리를 삭제한다. 삭제 시 해당 카테고리의 할일은 '기본' 카테고리로 자동 이관된다 (5장 규칙 7 참조) |

## 7. 필터링 기준 정의

할일 목록 조회 화면에서는 아래 필터를 제공하며, 카테고리 필터와 상태 필터는 동시에(AND 조건) 적용할 수 있다 (예: "업무" 카테고리 + "진행중" 조합 조회).

| 필터 | 기준 |
|---|---|
| 카테고리별 필터링 | 지정한 카테고리(또는 '기본' 카테고리)에 속한 할일만 조회 |
| 시작 전 할일 | 4장 기준 상태가 '시작 전(Not Started)'인 할일만 조회 |
| 진행중 할일 | 4장 기준 상태가 '진행중(In Progress)'인 할일만 조회 |
| 완료된 할일 | 4장 기준 상태가 '완료(Completed)'인 할일만 조회 |
| 기한초과 할일 | 4장 기준 상태가 '기한초과(Overdue)'인 할일만 조회 (종료일자 경과 + 미완료) |

필터를 지정하지 않으면 사용자 소유의 모든 할일을 조회한다.

## 8. 범위 외 사항 (Out of Scope)

본 문서(및 1차 개발 범위)에서는 다음 항목을 다루지 않는다.

- 할일 우선순위(중요도) 설정
- 마감 알림/푸시/이메일 알림 기능
- 반복 일정(매일/매주 등 recurring todo)
- 여러 사용자 간 할일 공유 또는 협업 기능
- 첨부파일, 댓글 등 부가 기능
- 소셜 로그인 등 외부 인증 연동
- 통계/리포트 대시보드
