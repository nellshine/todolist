## 1. 개요

### 1.1 목적

본 문서는 1인 개발자(본인)가 프론트엔드 화면을 실제 구현할 때 참고할 수 있도록, 화면별 레이아웃을
텍스트 기반 와이어프레임(ASCII 박스 다이어그램)으로 스케치한 것이다. 실제 그림 파일(Figma 등)이 아니라
개발 착수 전 화면 구조·요소 배치·반응형 재배치 방식에 대한 합의를 문서로 남기는 데 목적이 있다.

### 1.2 대상 화면 범위

PRD 5장 Must 기능(FR-1, 2, 3, 5, 6, 7, 8, 9, 10, 11, 12, 13)을 구현하는 화면을 중심으로 상세히 다루고,
Should 기능(FR-4 계정 정보 수정, FR-14 폼 유효성 인라인 메시지)은 간단히만 다룬다. Could(FR-15~17)와
Won't(FR-18) 관련 화면은 다루지 않는다.

### 1.3 반응형 작성 원칙

PRD 7.4절의 브레이크포인트를 기준으로, 각 화면은 원칙적으로 **데스크톱(1024px 이상)** 버전과
**모바일(~767px, 약 375px 기준)** 버전 두 가지 폭으로 각각 스케치한다. 태블릿(768~1023px)은 별도
와이어프레임을 그리지 않고, 데스크톱 레이아웃을 유지하되 사이드바 폭 축소 등으로 유연하게 대응하는 것을
원칙으로 한다(구현 시 CSS 미디어쿼리로 세부 조정).

## 4. 공통 UI 요소 설명

### 4.1 상태 표시 방식

할일 상태 4종(도메인 정의서 4장)은 다음과 같이 텍스트 + 색상 배지로 구분 표시한다. 색상 값 자체는
Could(FR-15~17) 범위의 상세 디자인 토큰 문서에서 확정하고, 본 문서에서는 구분 원칙만 정의한다.

| 상태 | 표시 텍스트 | 시각 강조 원칙 |
|---|---|---|
| 시작 전 (Not Started) | "시작 전" | 중립색(회색 계열) 배지 |
| 진행중 (In Progress) | "진행중" | 강조색(예: 파란색 계열) 배지 |
| 완료 (Completed) | "완료" | 완료 표시(체크 아이콘 채움) + 저채도 배지, 취소선 등 완료 인지 스타일 |
| 기한초과 (Overdue) | "기한초과" | 경고색(빨강/주황 계열) 배지 + 카드 테두리 강조로 가장 눈에 띄게 표시 |

- 상태 값은 프론트에서 계산하지 않고 백엔드 응답을 그대로 표시만 한다(FR-12, 4-project-structure.md 2.1절
  UI 레이어 원칙).
- 카테고리는 배지 형태(대괄호 `[카테고리명]`)로 제목 옆에 표시해 상태 배지와 시각적으로 구분한다.

### 4.2 반응형 재배치 원칙

- **데스크톱(1024px 이상)**: 2컬럼 레이아웃. 좌측 고정 사이드바(카테고리 필터 + 카테고리 관리 진입),
  우측 메인 영역(상태 필터 탭 + 할일 목록). 모달(등록/수정/삭제)은 화면 중앙 오버레이로 표시.
- **태블릿(768~1023px)**: 데스크톱과 동일한 2컬럼 구조를 유지하되 사이드바 폭을 축소한다(별도
  와이어프레임 없음, 1.3절 참조).
- **모바일(~767px)**: 1컬럼 레이아웃으로 전환. 사이드바 카테고리 필터는 상단 드롭다운(select)으로,
  상태 필터 탭은 그 아래 별도 드롭다운 또는 가로 스크롤 없는 토글 버튼 그룹으로 축소한다. 할일 목록은
  카드 단위로 세로 스택 배치한다. 모달(등록/수정/카테고리 관리)은 화면 하단에서 올라오는 풀스크린
  바텀시트 형태로 전환해 작은 화면에서도 입력 요소가 가로로 잘리지 않도록 한다(FR-13: 가로 스크롤 없이
  등록/필터/수정/삭제 조작 가능).
- 모든 브레이크포인트에서 "할일 추가" 버튼은 항상 화면 상단(또는 고정 위치)에서 노출되어 즉시 접근
  가능하도록 한다.

### 4.3 폼 유효성 피드백 (FR-14, Should)

- 필수 항목(제목, 시작일자, 종료일자) 미입력 또는 종료일자 < 시작일자 입력 시, 해당 입력 필드 바로
  아래에 인라인 에러 메시지(빨간색 텍스트)를 표시하고 저장을 차단한다.
- 별도의 토스트/얼럿 팝업 없이 폼 내부 인라인 메시지만으로 최소 구현한다(2일 일정 제약 반영).
