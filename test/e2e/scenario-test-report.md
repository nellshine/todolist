> 포함시켰으므로 `DELETE FROM users WHERE email LIKE '%.e2e.1785549000@example.com'` 한 줄로 정리 가능하다
> (users 삭제 시 categories/todos는 `ON DELETE CASCADE`로 함께 삭제됨, `docs/6-erd.md`).

  필요하다.

## 예외/에러 시나리오 상세 결과

### E-1. 종료일자가 시작일자보다 빠르게 입력됨 (도메인 규칙 3, FR-7)

- **클라이언트**: `TodoForm`에서 시작일자 2026-08-10 / 종료일자 2026-08-01로 입력 후 저장 클릭 →
  API 호출 없이 "종료일자는 시작일자보다 빠를 수 없습니다." 메시지를 보여주며 제출을 차단함(할일 미생성).
- **서버**: 동일한 값으로 `POST /todos`를 직접 호출한 결과 `400 { code: "INVALID_DATE_RANGE", message:
  "종료일자는 시작일자보다 이전일 수 없습니다." }` 확인 — 클라이언트 우회 시에도 서버가 동일 규칙을
  강제함을 확인.

### E-2. 다른 사용자 소유 리소스 ID로 조회·수정·삭제 시도 (도메인 규칙 4, FR-9~11)

지수 계정의 토큰으로 민준 소유 할일(`분기 보고서 작성`, 삭제 전 id)에 대해:

| 메서드 | 결과 |
|---|---|
| GET | `404 { code: "TODO_NOT_FOUND" }` |
| PATCH | `404 { code: "TODO_NOT_FOUND" }` |
| DELETE | `404 { code: "TODO_NOT_FOUND" }` |

403이 아닌 404로 일관되게 응답해 리소스 존재 여부 자체를 노출하지 않음을 확인.

### E-3. 인증 토큰 없음/위조 토큰으로 보호된 API 호출 (도메인 규칙 1, FR-3)

| 상황 | 결과 |
|---|---|
| `Authorization` 헤더 없이 `GET /todos` | `401 { code: "UNAUTHORIZED", message: "인증 토큰이 필요합니다." }` |
| 서명이 유효하지 않은 토큰으로 `GET /todos` | `401 { code: "UNAUTHORIZED", message: "유효하지 않은 토큰입니다." }` |

두 경우 모두 예외 없이 401로 일관되게 거부됨을 확인.

### E-4. 이미 가입된 이메일로 재가입 시도 (FR-1)

- 지수 계정 이메일로 다시 회원가입 시도 → 화면 이동 없이 "이미 가입된 이메일입니다." 에러 문구 노출,
  실제로 `POST /auth/signup`은 `409 { code: "EMAIL_ALREADY_EXISTS" }`로 응답함(콘솔 네트워크 로그로 확인).

## 부가 관찰 사항

- 모든 시나리오 진행 중 브라우저 콘솔에 기록된 "에러"는 전부 의도적으로 유발한 400/401/404/409 응답에 대한
  브라우저 자체의 네트워크 실패 로그였으며, 애플리케이션 코드에서 처리되지 않은 예외(런타임 크래시)는
  발생하지 않았다.
- 카테고리/할일 생성·수정·삭제 후 별도 새로고침 없이도 TanStack Query 캐시 무효화를 통해 목록이 즉시
  갱신되는 것을 모든 시나리오에서 일관되게 확인했다.
- 이번 라운드에서는 데스크톱 뷰포트(1280×900)만 사용했다. 반응형/모바일 크로스 브라우저 검증은 FE-9
  범위이며, 개별 FE 태스크 완료 시점(FE-1~FE-7)에 375px 등 모바일 뷰포트 검증을 별도로 수행한 바 있다
  (해당 이력은 이번 문서 범위 밖).
